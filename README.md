# 样本交接链路审计（Sample Chain-of-Custody Audit）

基于 **Python FastAPI + SQLite + 原生 HTML/CSS/JavaScript** 的样本交接链路审计网页。
为每个样本录入带有**时间区间**与**经手人**的交接事件后，系统按起始时间排序，
自动校验保管链路是否存在：

- 🔴 **保管断档（gap）**：上一任归还后、下一任接手前，存在无人负责的时间段；
- 🔴 **交接重叠（overlap）**：两个（含不相邻的）经手人在同一时间段同时持有样本，
  或上一任尚未归还下一任即接手；
- 🟠 **逆序录入（out-of-order）**：录入顺序（seq）与交接时间顺序不一致（事后补录）；
- 🔴 **起止倒置（reversed interval）**：单条事件结束时间早于起始时间。

时间线上以泳道条带展示各段保管区间，并叠加高亮断档（紫色斜纹）与重叠（红色）区域；
同时给出统计数字与**可读的中文审计结论**。支持编辑/删除事件，以及导出当前样本的
**Markdown / HTML / JSON** 审计报告。

审计完成后，审计员可对当前结论执行**结论签署**：填写签署人、签署时间与备注后，
系统保存一份包含样本信息、交接事件与审计发现的**不可变快照**（附 SHA-256 校验值）。
此后事件的任何增删改都不会改写历史快照；快照支持列表查看、详情核对与**撤销签署**
（撤销必须填写原因，原快照保留，仅标记状态）。导出的审计报告会自动附上签署记录。

系统还为每对按审计排序相邻的事件生成**双向交接确认**：交出方与接收方分别填写
确认人姓名和确认时间；只有**两侧均确认且上一段结束时间严格等于下一段开始时间**，
交接项才标记为「已确认」，否则显示「待确认」或「时间不一致」。每次确认都绑定
两条事件当时的关键字段摘要（经手人 / 起止时间 / 备注）并生成 SHA-256 摘要；任一
事件后续被编辑、删除，或新增事件导致两条记录不再相邻时，原确认保留为**失效记录**
（不再计入有效状态），必须由两侧重新确认。导出报告会逐项列出交接状态。

样本列表旁提供跨样本的**异常处置队列**：系统把全部样本的审计发现（断档 / 重叠 /
起止倒置 / 逆序录入 / 时间错误）汇总到一个队列，可按**异常类型、经手人、发生时间、
认领状态**筛选未处理项；每条未处理发现可由处置人**限时认领 15 分钟**——认领与
接管在单一事务内先重算发现，再同时校验 `expected_version` 与租约状态，未到期时
其他人收到 **409**，到期后任何人可**接管**（版本递增）。只有当前认领人可
**标记已处理**或**主动释放**；异常被系统消除时租约自动失效，复现后保持未认领。
每条发现可填写**处置人、备注**并**标记已处理**或**重新打开**。
发现身份由「样本 + 关联事件 + 异常类型 + 时间边界」生成 **SHA-256 稳定指纹**
（禁止按数组序号绑定）：链路编辑后自动重算——仍存在的发现**沿用处置状态**，
消失的转为**已消除历史**，新出现的保持**未处理**。队列入口显示未处理数角标，
每条发现可查看完整的**状态迁移记录**（含认领、释放、过期接管、租约失效）；
处置写入需携带客户端看到的指纹版本，过期请求返回 **409 冲突**并提示刷新。

每个交接事件还可上传**事件证据附件**（PDF / JPEG / PNG，单文件不超过 10 MiB）：
服务端**流式落盘**并计算 SHA-256，按摘要**内容寻址**——相同内容只存一份实体，
但每次上传都保留独立附件记录（原文件名、大小、上传人、时间、事件 ID）。下载前
服务端现场**复算摘要**，实体缺失或摘要不一致返回 **409** 并在列表中标为「损坏」，
可用「完整性刷新」重新复核（内容恢复后自动恢复正常）。删除附件只解除该条记录，
**最后一个引用移除后才清理实体文件**；有关联附件的事件 / 样本禁止删除，需先处理。
三种导出报告（Markdown / HTML / JSON）只列附件**元数据**，不含文件内容。

样本详情页提供**证据封存包**：一键导出 ZIP，包含 **JSON 清单**（样本、事件、附件的
逻辑关系与每个文件的路径、大小、SHA-256）、**Markdown 审计报告**与**全部未损坏
附件实体**（损坏附件排除出包并登记进清单）。生成时元数据在**同一数据库读事务**中
固定，写包前逐附件**复核摘要**；期间链路或附件记录发生变化即**中止**（409），
避免混合快照。另有**不落库校验入口**：上传封存包 ZIP 即可核对清单结构、缺失 /
多余文件与 SHA-256 摘要，限制解压总量、拦截路径穿越，差异以中文逐项列出。

样本详情页还提供**样本分装谱系**：每个样本在**首次分装前**必须先设置一次
**初始数量与计量单位**（如 `100 / mL`，之后初始数量与单位不可修改）。用户可从
**当前样本（含子样本）**发起一次分装，填写**多个子样本编号、名称（可选）与各自
分装量**；服务端以 Python `decimal.Decimal` **精确十进制**（拒绝浮点数与科学
计数法，杜绝 `0.1 + 0.2` 误差）在**单一写事务**（`BEGIN IMMEDIATE`）内校验：
子样本编号**全局唯一**（请求内重复 / 与既有编号冲突均拒绝）、**单位继承一致**、
每个分装量为**严格正数**、合计为正且**不超过父样本当前可用余量**。校验通过后在
同一事务内创建全部子样本（各自初始数量 = 本次分装量）、按合计**扣减父样本余量**、
并保存一条**不可变批次**（含父子明细与 SHA-256 快照）；任何一步失败整体回滚，
**绝不产生部分记录**。请求必须携带父样本当前版本号 `expected_version`（乐观锁），
**重复提交**（编号已被首次提交占用）或**并发变更**（版本过期 / 余量不足）一律
返回 **409**。详情页以**父子树**展示每个样本的来源批次、分装量、初始量与
剩余量，可一键进入任意子样本**继续分装**；点击批次号打开**批次详情**（批次头、
余量变化、明细与快照完整性校验）。**已有后代、或本身由批次产生的样本禁止删除**
（批次与明细永久不可变）。

系统还提供**样本库位管理**：用户可创建带**全局唯一编号与容量**的库位
（如 `LOC-A-01 · 冷藏柜 A-1 · 容量 8`），并将样本**放入**、在库位间**转移**
或**移出**；**每个样本最多占一个库位**。每次移动在单一 `BEGIN IMMEDIATE`
事务内校验**样本当前库位**（陈旧来源拒绝）、**目标剩余容量**，以及**样本和
源 / 目标库位的 `expected_version`**（乐观锁）；成功后在同一事务内同步增减两侧
占用数、更新样本当前位置与版本，并写入一条**不可变移动记录**。**并发争抢最后
空位、陈旧来源或版本过期均返回 409**，任何失败整体回滚——绝不产生重复占位、
超容量或半条记录。左侧「🗄 样本库位管理」视图展示全部库位的**占用清单**
（容量 / 已占用 / 剩余 / 占用率），样本详情页「样本库位」卡片展示**样本当前
位置**与**移动历史**；库位中的样本禁止删除（需先移出）。

## 快速开始（Docker Compose，推荐）

```bash
docker compose up -d --build
```

启动后访问固定端口：

> http://localhost:8080

容器启动时会自动完成：

1. 安装 Python 依赖（镜像构建阶段）；
2. 初始化 SQLite（建表，写入 2 个演示样本与 2 个演示库位，数据文件位于
   `/data/audit.db`，通过命名卷 `audit-data` 持久化）；创建证据附件目录
   `/data/attachments`（同样位于 `audit-data` 卷，容器重建后已上传附件不丢失）；
3. 启动 uvicorn 监听 `8080`。

**数据位置**：数据库与附件实体都保存在命名卷 `audit-data` 中——

| 数据 | 容器内路径 | 说明 |
| --- | --- | --- |
| SQLite 数据库 | `/data/audit.db` | 样本 / 事件 / 签署 / 交接确认 / 异常队列 / 附件记录 / 分装批次谱系 / 库位与移动记录 |
| 证据附件实体 | `/data/attachments/` | 按 SHA-256 两级分片内容寻址（`ab/cd/<64hex>`） |

停止 / 清理：

```bash
docker compose down          # 停止并删除容器（保留数据卷）
docker compose down -v       # 同时删除数据库与附件数据卷
```

## 本地开发运行（不用 Docker）

需要 Python 3.11+：

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt

uvicorn app.main:app --host 0.0.0.0 --port 8080 --reload
```

数据库默认创建在 `app/audit.db`（首次启动自动建表并写入演示数据）。
可通过环境变量 `AUDIT_DB_PATH` 自定义路径。证据附件实体默认存放在数据库文件
旁的 `attachments/` 目录（本地开发即 `app/attachments/`），可用环境变量
`ATTACHMENT_DIR` 覆盖（容器内为 `/data/attachments`）。

运行测试：

```bash
pytest -q
```

## 使用说明

1. 点击右上角 **＋ 新建样本**（编号唯一），或从左侧选择演示样本；
2. 在「交接事件」卡片填写经手人、起始时间、结束时间（**留空表示当前仍在保管中**）、备注，
   点击 **登记交接事件**；
3. 审计结论、统计与时间线实时刷新。时间条按起始时间排列，冲突事件标红，
   点击下方「审计发现」条目可高亮对应的时间条与表格行；
4. 点击事件行的 **编辑** 可修改任意字段（录入序 seq 保持不变，便于追溯补录行为），
   保存后重新审计；也可删除事件；
5. 在「结论签署」卡片填写签署人、签署时间（默认当前时间）与备注，点击
   **签署当前审计结论** 生成不可变快照；列表中点击 **详情 / 撤销** 可查看快照完整内容
   （含完整性校验），有效签署可在详情弹窗中填写原因后撤销，撤销后原快照保留；
6. 在「双向交接确认」卡片可看到按审计排序生成的全部交接项：点击 **填写确认**，
   在弹窗中选择交出方 / 接收方并填写姓名与确认时间（默认当前时间）；两侧均确认后
   系统按交接时点判定「已确认」或「时间不一致」。事件被编辑、删除或相邻关系变化后，
   原确认会移入下方「失效的历史确认」列表，可查看绑定摘要，交接项需重新确认；
7. 通过「交接事件」卡片右上角的 **导出审计报告** 下载 Markdown / HTML / JSON 三种格式之一，
   报告末尾自动附上全部签署记录（含状态与撤销原因）以及各交接项的确认状态；
8. 需要一次录入多条事件时，点击「交接事件」卡片右上角的 **⇪ 批量导入 CSV**：
   先 **⇩ 下载 CSV 模板**，按格式填写 UTF-8 CSV 后选择文件并点击 **解析并预览**；
   预览逐行列出校验错误，并对照展示导入前后审计结论、统计与交接确认失效变化，
   **预览阶段不写库**；仅当全部行校验通过时才能 **确认导入**（详见下节）。
9. 点击左侧样本列表上方的 **🚨 异常处置队列**（红色角标为当前未处理数）进入
   跨样本队列：默认列出全部样本的**未处理**审计发现，可按异常类型、经手人
   （模糊匹配）、发生时间区间、状态与**认领状态**（未认领 / 认领中 / 已过期）
   筛选；队列显示每条发现的认领人与**租约剩余时间**（每秒倒计时，到期自动刷新）。
   对未认领的发现点击 **认领** 即获得 **15 分钟**处置租约，租期内可 **处置**
   （标记已处理）或 **释放**（主动让出）；其他人在租期内点击只会收到冲突提示，
   租约到期后行上出现 **接管** 按钮，任何人可接管并获得新的 15 分钟租约。
   **只有当前认领人**可以标记已处理或主动释放；异常被链路修复而消除时租约
   自动失效，异常复现后保持未认领。已处理项可 **重新打开**；点击 **迁移记录**
   查看该发现从首次出现到当前的全部迁移（含限时认领、主动释放、过期接管、
   租约失效等事件及系统自动迁移）。链路编辑后队列自动重算：
   仍存在的发现沿用处置状态，消失的转为「已消除」历史（状态筛选中可查），
   新出现的保持未处理。若提交时提示指纹版本冲突（409），说明期间数据已被
   他人更新或链路已变化，队列会自动刷新，请基于最新状态重试（详见下节）。
10. 在事件行点击 **📎 附件** 管理该事件的证据附件：选择 **PDF / JPEG / PNG**
    （单文件不超过 **10 MiB**）并填写上传人后点击 **⇪ 上传附件**，服务端流式
    落盘并按 SHA-256 内容寻址（相同内容只存一份实体，每次上传保留独立记录与
    原文件名）；列表给出原文件名、类型、大小、上传人、上传时间、摘要与完整性
    状态，可 **下载**（下载前服务端复算摘要，缺失 / 不一致返回 409）、**删除**
    （仅解除本记录，最后一个引用移除后才清理实体）与 **复核 / 完整性刷新**。
    实体缺失或被篡改的附件会标红为「损坏」，内容恢复后点击复核即可恢复正常。
    **有关联附件的事件（及其样本）不能直接删除**，页面与接口都会提示先处理附件。
11. 在「证据封存包」卡片点击 **🗜 导出封存包（ZIP）**：包内含 JSON 清单、
    Markdown 审计报告与全部未损坏附件实体；若存在损坏附件，导出前会提示其将被
    排除并登记进清单。导出失败（如生成期间链路或附件记录被他人变更）时，失败
    原因直接展示在卡片中。拿到封存包后，可在同一卡片选择 ZIP 文件点击
    **校验封存包**：不读取数据库、不修改任何数据，逐项核对清单声明、缺失与
    多余文件、大小及 SHA-256 摘要，校验结论与中文差异列表展示在卡片中。
12. 在「样本分装谱系」卡片管理样本数量与分装：
    - **首次分装前**，未设置数量的样本显示初始化表单，填写**初始数量**（精确
      十进制，如 `100`、`0.250`）与**计量单位**（如 `mL`、`g`、`支`），提交时
      携带样本当前版本；初始数量与单位**仅可设置一次**，之后不可修改；
    - 设置后在同一卡片点击 **＋ 添加子样本**，逐行填写**子样本编号（全局唯一）、
      名称（可选）与分装量**，填写操作人（分装时间留空取服务端当前时间）后点击
      **执行分装**。服务端按精确十进制校验编号唯一、单位一致、分装量为正且合计
      不超过可用余量；成功后子样本创建、父余量扣减与不可变批次在单一事务内一并
      落库，页面刷新父子树并在左侧列表出现新子样本；
    - 若提示 **409 冲突**（编号重复 / 合计超余量 / 版本过期），页面会自动按
      服务端最新状态刷新，核对后重试即可——**重复点击提交不会产生任何部分记录**；
    - 下方**父子树**以根样本为顶展示整个家族：每行给出初始数量 → 当前剩余量、
      **来源批次号、分装量、分装时间与操作人**；点击 **进入并继续分装** 可直接
      跳转到任意子样本（孙样本）继续发起分装，点击蓝色**批次号**打开批次详情
      （不可变明细、余量前后变化、SHA-256 快照完整性校验）；
    - **已有分装后代、或本身由批次产生的样本禁止删除**（删除按钮返回 409，
      批次记录永久保留）。演示样本 `SAM-DEMO-001` 已预置「父 100 mL → 子样本
      A 60 mL / B 30 mL → 孙样本 A-1 20 mL」两级谱系，开箱即可查看。
13. 点击左侧样本列表上方的 **🗄 样本库位管理** 进入库位视图：上方表单创建
    **带唯一编号与容量**的库位（如 `LOC-C-03 · 冷藏柜 C-3 · 容量 8`），列表
    实时展示每个库位的**容量 / 已占用 / 剩余空位 / 占用率**；点击 **占用清单**
    打开库位详情弹窗，查看当前存放的样本（可直接**进入样本**）与涉及该库位的
    **移动历史**。回到样本详情页的「样本库位」卡片：顶部显示**样本当前位置**
    （未入库 / 所在库位与放入时间），选择**目标库位**（仅列出有空位的库位，
    已满的置灰）并填写操作人后点击 **放入 / 转移到目标库位**，已入库的样本
    还可 **移出库位**；下方表格列出该样本的全部**移动历史**（不可变记录）。
    提交时自动携带样本与源 / 目标库位的当前版本做乐观锁校验——若期间被他人
    转移、目标空位被抢或版本过期，服务端返回 **409**，页面自动按最新状态刷新，
    核对后重试即可；**并发争抢最后空位也只有一人成功，绝不超容量或重复占位**。

### 批量导入 CSV 格式与操作入口

- 入口：样本详情页「交接事件」卡片右上角 **⇪ 批量导入 CSV**（也可直接 GET
  `/api/samples/{id}/events/import-template` 下载模板）；
- 文件编码必须为 **UTF-8**（带不带 BOM 均可；模板自带 BOM，Excel 直接打开不乱码），
  单次最多 1000 行、5MB；
- 表头固定为且只能是以下 4 列（首行）：

  | 列名 | 必填 | 格式 / 说明 |
  | --- | --- | --- |
  | 经手人 | 是 | 1~64 字符，前后空格自动去除，不能为空 |
  | 开始时间 | 是 | `YYYY-MM-DD HH:MM:SS`（也兼容 `YYYY-MM-DDTHH:MM:SS` 与只到分钟） |
  | 结束时间 | 否 | 同上；**留空表示当前仍在保管中**，且不能早于开始时间 |
  | 备注 | 否 | 最长 512 字符；内容含英文逗号时用英文双引号包裹，如 `"运输, 2-8℃"` |

- 校验规则与单条录入完全一致（共用同一套输入模型）；任一行有错则整批不可导入，
  错误逐行标注在预览表中，修正文件后重新预览即可；
- 预览返回绑定 **当前事件链指纹** 的签名摘要令牌（10 分钟有效）。确认导入时必须
  携带该令牌，服务端在单一事务（`BEGIN IMMEDIATE`）内重新校验：预览之后该样本的
  事件链发生任何增、删、改，都会以 409 拒绝并提示重新预览；令牌篡改、过期、跨样本
  或重复使用同样被拒绝；
- 全部行再次校验通过后，才按 **文件行顺序** 一次性分配录入序 seq 写入，并统一刷新
  交接确认失效状态（新事件插入相邻事件之间会使原确认按 `adjacency_changed` 失效，
  原记录保留）；任一环节失败整体回滚，不存在部分落库；
- 导入成功后页面给出结果汇总（导入条数、seq 区间、失效确认数量与原因、导入后审计
  结论），并自动刷新时间线、事件表与交接确认。

演示样本 `SAM-DEMO-001` 预置了断档、重叠与逆序补录，`SAM-DEMO-002` 是无缝链路，
开箱即可对比两种审计结果。此外 `SAM-DEMO-001` 还预置了两级**分装谱系**
（父样本 100 mL → 子样本 A 60 mL / B 30 mL，A 再分装出孙样本 A-1 20 mL，
父样本当前剩余 10 mL），进入该样本的「样本分装谱系」卡片即可查看父子树与
不可变批次。库位方面预置了 `LOC-A-01`（冷藏柜 A-1，容量 8）与 `LOC-B-02`
（冷冻柜 B-2，容量 4）两个演示库位，`SAM-DEMO-002` 已放入 `LOC-A-01`
（含一条「初始入库」移动记录），左侧「🗄 样本库位管理」与样本详情页的
「样本库位」卡片开箱即可查看占用清单、当前位置与移动历史。

## 审计规则说明

| 规则 | 判定方式 | 级别 |
| --- | --- | --- |
| 断档 gap | 按起始时间排序后，相邻两段 `cur.start > prev.end`，差值即断档时长 | 冲突（审计不通过） |
| 重叠 overlap | 相邻段 `cur.start < prev.end`；开放保管（无结束时间）之后又出现新段；以及任意两段非相邻区间的时间交叉 | 冲突 |
| 起止倒置 | 单条事件 `end < start` | 冲突（该条不参与区间链计算） |
| 逆序录入 | 时间更早的事件录入序 `seq` 反而更大 | 告警（链路本身可通过） |

结论分三档：`pass`（无缝衔接）、`warning`（链路连续但存在逆序补录）、
`fail`（存在断档/重叠/倒置）。

## 双向交接确认

- 交接项由系统按审计排序（起始时间升序；起止倒置事件不参与）的**相邻事件对**
  自动生成，上一段为交出方、下一段为接收方，无需手工配对；
- 状态机：

  | 状态 | 判定 |
  | --- | --- |
  | 已确认 confirmed | 交出方、接收方均已填写姓名与确认时间，且交出结束时间 = 接收开始时间 |
  | 待确认 pending | 尚未两侧齐全（含只有一侧确认），或时间一致但等待另一侧 |
  | 时间不一致 time_mismatch | 两侧均已确认，但交出结束时间 ≠ 接收开始时间（含交出方仍在保管） |

- 每条确认在**首次发起时**绑定两条事件当时的关键字段摘要（经手人、起始时间、
  结束时间、备注）并记录 SHA-256 摘要；
- 事件被编辑（任一字段变化）→ 原确认以 `event_edited` 失效；事件被删除 →
  `event_deleted`；新增 / 调整事件导致两事件不再相邻 → `adjacency_changed`。
  失效只更新状态 / 原因 / 失效时间，原行与快照永久保留，不再计入交接项有效状态，
  必须两侧重新确认（重新确认生成新记录）。

## 异常处置队列

- **入口**：左侧样本列表上方的「🚨 异常处置队列」按钮，红色角标实时显示
  **未处理数**；点击后主区域切换为跨样本队列视图，点击任一样本即返回详情页；
- **发现身份（稳定指纹）**：每条审计发现以
  `SHA-256(样本 + 关联事件 id + 异常类型 + 时间边界)` 为唯一身份，
  **与列表顺序、数组序号无关**。指纹输入中不含经手人姓名与消息文本，
  因此仅修改经手人 / 备注时指纹不变、处置状态完整沿用；
- **链路编辑后重算**（事件增删改、批量导入、查看队列时自动触发，幂等）：

  | 重算结果 | 处理 |
  | --- | --- |
  | 指纹仍存在 | 同一条发现，沿用原处置状态（仅刷新消息快照与最近出现时间） |
  | 指纹消失 | 转为「已消除」历史，原记录与处置信息保留，不计入未处理数 |
  | 指纹新出现 | 以「未处理」入库；若命中已消除记录（同一异常复现），恢复原记录为未处理 |

- **处置操作**：未处理项必须先**限时认领**才可标记已处理；已处理项可
  **重新打开**回到未处理（重新打开后为未认领状态）；已消除项为只读历史。
  每次状态迁移（含首次出现、系统自动消除 / 复现、认领 / 释放 / 接管）都写入
  迁移记录，点击「迁移记录」可查看完整时间线；
- **限时认领（15 分钟租约）**：

  | 操作 | 规则 |
  | --- | --- |
  | 认领 claim | 仅未处理发现可认领；同一认领人重复认领幂等（不续期、不递增版本） |
  | 冲突 | 租约未到期且认领人是别人时，认领 / 接管返回 **409**（即使携带最新版本） |
  | 过期接管 takeover | 租约到期后任何人可认领接管，写入新认领人与到期时间，**版本 +1** |
  | 主动释放 release | 只有当前未到期租约的认领人可释放；释放后版本 +1、立即回到未认领 |
  | 标记已处理 resolve | 只有**当前认领人**（且租约未到期）可执行，处置后租约清空 |
  | 系统消除 | 异常随链路变更消除时租约自动失效（`lease_void` 留痕）；复现后保持未认领 |

  认领 / 接管 / 释放 / 处置都在单一写事务（`BEGIN IMMEDIATE`）内**先按当前链路
  重算发现**，再以条件 UPDATE **同时**校验 `expected_version` 与租约状态
  （`version = ? AND … AND (claimed_by IS NULL OR claimed_by = ? OR claim_expires_at <= now)`），
  从根本上杜绝「两人同时认领成功」。租约时长默认 900 秒，可用环境变量
  `FINDING_CLAIM_TTL_SECONDS` 覆盖（仅对新发起的认领生效）；
- **并发保护（指纹版本）**：每条发现维护递增版本号，任何状态迁移（含认领 /
  接管 / 释放）都会使其 +1。
  处置写入必须携带客户端看到的 `expected_version`；服务端先按当前链路重算
  指纹再比对版本，过期请求返回 **409 冲突**，前端收到冲突后自动刷新队列；
- **筛选**：异常类型（断档 / 重叠 / 起止倒置 / 逆序录入 / 时间错误）、经手人
  （对关联事件经手人做模糊匹配）、发生时间区间（与发现的时间边界相交即命中，
  开放保管视为无限远）、状态（未处理 / 已处理 / 已消除 / 全部）、认领状态
  （未认领 `unclaimed` / 认领中 `claimed` / 已过期可接管 `expired`，仅作用于
  未处理发现）；每条未处理发现返回 `claim_state`、`claimed_by`、
  `claim_expires_at` 与 `claim_remaining_seconds`（剩余秒数）。
  顶部统计（未处理 / **认领中** / 已处理 / 已消除 / 累计）为全局数字，不受筛选影响。

## 事件证据附件

- **类型与大小**：仅支持 **PDF（.pdf）/ JPEG（.jpg/.jpeg）/ PNG（.png）**，
  服务端按文件头魔数识别真实类型（扩展名与声明 Content-Type 一并校验），
  单文件不超过 **10 MiB**（流式读取，超限立即以 413 拒绝，不占满内存）；
- **内容寻址去重**：上传时以 1 MiB 分块流式写入附件目录下的临时文件，同时
  计算 SHA-256；落盘实体路径为两级分片 `ATTACHMENT_DIR/<前2位>/<次2位>/<64位摘要>`。
  相同内容（即使原文件名不同、属于不同事件）只存**一份实体**（`attachment_blobs`），
  但每次上传都生成**独立附件记录**（`attachments`：原文件名、大小、类型、
  上传人、上传时间、事件 ID）；
- **下载前复算摘要**：下载接口现场重新流式读取实体并复算 SHA-256 与大小，
  实体缺失标记 `missing`、内容不一致标记 `digest_mismatch`，二者都返回
  **409 冲突**（不返回文件），并把该记录状态置为「损坏」；列表接口做轻量
  存在性检查（缺失即标损），**完整性刷新**（单条 / 整事件）才做全量复算，
  内容恢复后刷新可使状态恢复 `ok`；
- **删除引用计数**：删除附件只删除 `attachments` 中的该条记录；在
  `BEGIN IMMEDIATE` 事务内检查引用计数，**最后一个引用移除后**才删除实体文件
  与 `attachment_blobs` 行，并清理空的分片目录；上传去重与删除清理由进程锁
  串行化，避免并发删除误删另一上传刚引用的实体；
- **删除保护**：只要事件下还存在附件记录，删除事件返回 **409**；样本下任一
  事件仍有附件时删除样本同样返回 **409**，提示先处理（删除）附件；
- **报告**：Markdown / HTML / JSON 三种报告只列附件**元数据**（所属事件、
  原文件名、类型、大小、上传人 / 时间、SHA-256、完整性状态），不嵌入文件内容、
  不提供下载地址；
- **持久化**：容器内附件目录为 `/data/attachments`，与数据库同在命名卷
  `audit-data`；本地开发默认 `app/attachments/`（可用 `ATTACHMENT_DIR` 覆盖）。

## 证据封存包

- **入口**：样本详情页「证据封存包」卡片（http://localhost:8080 ，选择样本后
  可见）；API 为 `GET /api/samples/{id}/seal-package`（导出）与
  `POST /api/seal-packages/verify`（校验），服务固定端口 **8080**；
- **包内结构**：`seal_package_<编号>_<时间戳>/` 目录下含
  `manifest.json`（JSON 清单）、`report.md`（Markdown 审计报告）与
  `attachments/<事件id>/<附件id>_<原文件名>`（全部未损坏附件实体）。
  清单记录样本、事件、附件的逻辑关系（事件 → 附件 id 列表），以及包内每个
  文件（报告 + 附件）的**路径、大小与 SHA-256**；损坏附件不进包，登记在
  清单 `excluded_attachments` 中（含损坏原因）；
- **一致性（避免混合快照）**：导出分两阶段——先在**同一数据库读事务**中读取
  样本 / 事件 / 附件记录等元数据并计算链路指纹；随后逐附件**复核实体 SHA-256**
  （损坏者排除）；写包前开启第二个读事务重读元数据并比对指纹，**期间链路或
  附件记录任何变化即中止（409）**；ZIP 在同一读事务内写出，每个附件写入时
  再次流式复算摘要，与清单不一致同样中止；
- **不落库校验**：`POST /api/seal-packages/verify` 接收 ZIP 文件（multipart
  `file` 字段），**不读写数据库、不解压落盘**：限制上传大小（300 MiB）、
  条目数、单文件（64 MiB）与**解压总量**（512 MiB），拦截**路径穿越**条目
  （`..` / 绝对路径 / 盘符 / 反斜杠）；逐项核对清单结构、**缺失**、**多余**
  文件与 **SHA-256 摘要**，返回中文差异列表（`valid` / `issues` / `summary`），
  页面卡片同步展示校验结论。

## 样本分装谱系

- **数量模型**：每个样本有 `initial_quantity` / `remaining_quantity`（规范十进制
  文本，如 `"100.00"`、`"0.30"`）与 `unit`，首次分装前必须调用
  `PUT /api/samples/{id}/quantity` 设置**一次**（此后初始数量与单位不可修改，
  重复设置返回 409）；`version` 为样本级乐观锁，设置数量与每次成功分装都会
  使其 +1；
- **精确十进制**：数量以**字符串 / 整数**提交，服务端用 `decimal.Decimal`
  归一化（去除多余 0、拒绝非有限数）与求和比较；**拒绝 `float`**（避免二进制
  误差）与**科学计数法**，要求普通十进制写法；限制总整数位 ≤ 30、小数位 ≤ 10，
  单位最长 16 字符；保证 `0.1 + 0.2 == 0.3` 且边界「合计 = 余量」精确成立；
- **单位一致**：子样本不接受单位参数，**直接继承父样本单位**，因此同一谱系内
  单位天然一致；
- **编号唯一**：子样本编号复用 `samples.code` 的全局唯一约束。事务内先校验
  请求内不重复、再逐行校验与既有样本不冲突；第一次成功提交后再次提交（重试 /
  双击）会因编号已被占用而返回 **409**；
- **单事务 + 乐观锁**：分装在 `BEGIN IMMEDIATE` 单一写事务内执行
  「校验版本 → 校验编号 / 数量 / 余量 → 写批次 → 建子样本 → 写明细 →
  条件更新（`WHERE version = ?`）扣减余量并 +1」，任一步失败整体 `ROLLBACK`，
  批次、子样本、明细与余量扣减要么全部成功、要么全部不存在；
  并发请求在写锁上排队，后到者因版本不匹配 / 编号冲突返回 409，
  从根本上杜绝超扣与部分落库；
- **不可变批次**：`aliquot_batches`（批次头：批次号、父样本、父版本、单位、
  合计、余量前后、操作人、时间、备注）与 `aliquot_items`（逐子样本分装量明细）
  一经写入**无任何更新 / 删除接口**；批次 `snapshot` 固化父样本当时状态与全部
  子样本分装量并计算 SHA-256，`GET /api/aliquot-batches/{id}` 现场复算摘要给出
  `integrity_ok`；
- **父子树**：`GET /api/samples/{id}/lineage`（样本详情接口也内联 `lineage`）
  以 `parent_sample_id` 递归 CTE 上溯谱系根、向下展开全部后代；每个非根节点带
  `via_batch`（来源批次、分装量、单位、时间、操作人）。从任意子样本发起分装
  即生成新的批次边，形成多级树；
- **删除保护**：删除样本前检查谱系——`parent_sample_id / batch_id` 非空（由批次
  产生）或仍存在子样本（有后代）的样本一律 **409**；批次外键不做级联删除，
  历史批次永久可查。旧版本库启动时自动补齐谱系列与索引（幂等迁移）。

## 样本库位管理

- **库位模型**：`locations` 表存全局唯一编号、名称、容量（正整数）、当前占用数
  `occupied`（事务内维护的冗余计数，`CHECK (occupied >= 0)` 兜底）与乐观锁
  `version`（每次占用变化 +1）；创建接口 `POST /api/locations`，编号重复返回
  **409**，容量 / 编号 / 名称形态错误返回 422；
- **每样本最多一个库位**：`sample_placements` 以 `sample_id` 为主键记录样本当前
  所在库位（未入库则无行），从结构上杜绝一样本多占位；
- **单事务转移**：`POST /api/samples/{id}/location-move` 支持放入（声明源为
  `null`）、库位间转移与移出（`to_location_id` 为 `null`）。服务端在单一
  `BEGIN IMMEDIATE` 事务内依次校验：样本存在且 `expected_sample_version` 一致
  → 样本当前库位与声明的 `expected_from_location_id` 一致（**陈旧来源**拒绝）
  → 目标不是当前所在库位（重复占位拒绝）→ 目标库位存在、版本一致且
  `occupied < capacity` → 源库位版本一致；随后以**条件 UPDATE**
  （`WHERE id = ? AND version = ? AND occupied < capacity` 等）同步增减两侧
  占用数并各 +1 版本、更新样本当前位置与样本版本，最后写入一条**不可变移动
  记录**（`location_moves`，含样本 / 库位编号快照与三方版本快照，无更新 /
  删除接口）。任一步失败整体 `ROLLBACK`——**并发争抢最后空位、陈旧来源或
  版本过期均返回 409**，绝不产生重复占位、超容量或半条记录；
- **页面**：左侧「🗄 样本库位管理」视图创建库位并展示全部库位的容量 / 已占用 /
  剩余 / 占用率，「占用清单」弹窗给出库位当前存放样本与移动历史；样本详情页
  「样本库位」卡片展示**样本当前位置**、**移动历史**，并提供放入 / 转移 / 移出
  表单（自动携带三方版本，409 后自动刷新）；样本详情接口内联 `location` 与
  `location_moves`；
- **删除保护**：样本当前位于库位中时删除返回 **409**（提示先移出库位），
  避免占用计数静默失真；移出后可正常删除，历史移动记录以编号快照永久保留。

## 技术说明

- 时间存储为 SQLite 文本 `YYYY-MM-DD HH:MM:SS`，应用层统一解析为 naive datetime 比较；
- `events.seq` 为不可变的录入顺序（自增），审计排序按 `start_time`，二者不一致即为逆序录入；
- 签署快照以 JSON 文本整体存入 `signoffs.snapshot`，并记录 SHA-256 校验值；
  撤销仅更新 `status / revoke_reason / revoked_at`，快照内容从创建起无任何接口可修改；
- 双向交接确认存于 `handovers` 表：两侧确认列、两条事件确认当时的关键字段 JSON 摘要
  与合并 SHA-256；事件编辑 / 删除 / 相邻关系变化只把原行置为 `invalidated`
  （记录原因与失效时间），原行不删除、不计入有效状态；`handovers` 的事件列不加
  级联外键，事件删除后失效记录仍可查，删除样本时随样本一并级联清除；
- 批量导入为无状态两段式：预览令牌是 `base64url(payload).base64url(HMAC-SHA256)`，
  进程内随机密钥签名（服务重启后旧令牌自然失效，重新预览即可），载荷含样本 id、
  规范化后的全部行、过期时间与 **预览当时的事件链指纹**（全部事件字段的
  SHA-256）；确认时先 `BEGIN IMMEDIATE` 取写锁再重算指纹，杜绝并发写入造成的
  覆盖；整个确认在一个 SQLite 事务内完成，失败一律 `ROLLBACK`，不部分落库；
- 异常处置队列存于 `findings` / `finding_transitions` 两表：发现身份为
  `SHA-256(样本 + 关联事件 + 异常类型 + 时间边界)` 稳定指纹（唯一约束），
  **不按数组序号绑定**；事件增删改、批量导入与队列读取时都会重算指纹并比对——
  仍存在沿用处置状态、消失转 `eliminated` 历史（未到期认领租约随之清空并写
  `lease_void` 记录）、复现恢复 `open`（未认领）、新出现未处理，
  全部迁移（含系统自动迁移与认领类事件 `claim` / `release` / `takeover` /
  `lease_void`，由 `finding_transitions.event` 区分）写入迁移记录表；
  `findings.claimed_by / claimed_at / claim_expires_at` 为限时认领租约三列，
  认领 / 接管 / 释放 / 处置用 `BEGIN IMMEDIATE` 单事务包裹「先重算指纹，
  再条件 UPDATE 同时校验版本与租约」做乐观锁，版本过期或租约冲突返回 409，
  客户端刷新后重试；租约默认 15 分钟（`FINDING_CLAIM_TTL_SECONDS` 可覆盖）；
  旧版本库启动时自动补齐新增列（轻量幂等迁移，演示数据不受影响）；
  删除样本时两级记录随样本级联清除；
- 无外部前端构建步骤，静态资源由 FastAPI 的 `StaticFiles` 直接提供；
- 证据附件存于附件目录的两级分片路径（`<前2位>/<次2位>/<完整 SHA-256>`）与
  `attachment_blobs`（去重实体）/ `attachments`（每次上传的独立记录）两表；
  上传以 1 MiB 分块流式写入临时文件并同步计算摘要，按内容原子移入分片目录，
  相同内容只存一份；删除仅删记录，`BEGIN IMMEDIATE` 事务内引用计数归零后才
  清理实体（进程锁串行化去重 / 清理）；下载与刷新现场复算 SHA-256，失败置
  `corrupt`（`missing` / `digest_mismatch`）并以 409 拒绝下载；有关联附件的
  事件 / 样本删除一律 409 拒绝；
- 证据封存包导出为「读事务固定元数据 → 复核附件摘要 → 读事务比对链路指纹 →
  同事务写 ZIP」两阶段流程：链路（样本 / 事件）或附件记录在两阶段间变化即
  以 409 中止，写包时逐附件再次流式复算 SHA-256；清单 `manifest.json` 记录
  样本 / 事件 / 附件逻辑关系与每个包内文件的路径、大小、SHA-256，损坏附件
  排除出包并登记 `excluded_attachments`；校验入口为纯函数（不读写数据库、
  不落盘解压），按条目数 / 单文件 / 解压总量限额与路径穿越规则先过滤，
  再逐项核对缺失、多余与摘要，差异以中文返回；
- 样本分装谱系在 `samples` 上扩展初始 / 剩余数量（规范十进制文本）、单位、
  乐观锁 `version` 与谱系来源（`parent_sample_id` / `batch_id`），另设
  `aliquot_batches` / `aliquot_items` 两张不可变表（含 SHA-256 快照）。
  数量仅接受字符串 / 整数并以 `Decimal` 精确归一化（拒绝 float 与科学计数法，
  限制整数位 ≤ 30、小数位 ≤ 10）；分装在 `BEGIN IMMEDIATE` 单事务内完成
  「版本校验 → 编号唯一 / 单位继承 / 为正 / 合计不超余量校验 → 批次 + 子样本
  + 明细写入 → 条件 UPDATE 扣减余量（`WHERE version = ?`）」，失败整体回滚，
  重复提交（编号占用）/ 并发变更（版本过期）一律 409、无部分记录；
  子样本继承父单位并可继续分装形成多级树；已有后代或批次来源的样本禁止删除；
  旧版本库启动时自动补齐谱系列与索引（幂等迁移）；
- 样本库位管理由 `locations`（唯一编号 + 容量 + 事务内维护的 `occupied` 计数 +
  乐观锁 `version`）、`sample_placements`（`sample_id` 主键，保证每样本最多
  一个库位）与 `location_moves`（不可变移动记录，含编号与三方版本快照，无
  更新 / 删除接口）三表组成；移动（放入 / 转移 / 移出）在 `BEGIN IMMEDIATE`
  单事务内完成「样本版本校验 → 当前库位（陈旧来源）校验 → 目标存在 / 版本 /
  剩余容量校验 → 源版本校验 → 条件 UPDATE 增减两侧占用并各 +1 版本 → 更新
  样本当前位置与版本 → 写移动记录」，失败整体回滚，并发争抢最后空位、陈旧
  来源或版本过期一律 409，绝不产生重复占位、超容量或半条记录；样本当前位于
  库位中时禁止删除（409），移动记录以编号快照在样本删除后仍可查；
- 服务进程在容器内以非 root 友好的方式运行于固定端口 **8080**，数据与镜像分离。
